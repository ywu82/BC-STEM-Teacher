# 06 Results → evidence → actions
Intake anonymized student×item points and item blueprint with OIDs. Reject invalid types, duplicate rows, negative/over-max scores, unknown OIDs and denominator=0. Include missingness separately. For each assessment, calculate the highest, lowest, mean and median percentage from complete responses only; label that denominator and never silently treat partial or missing work as zero. Produce sample size, distributions, per-objective earned/possible percentages, shares above teacher-defined targets, diagnostic prerequisite flags, quiz/test attainment, student-level privacy-safe actions, next lesson changes, matched-item caveats, interpretation limits.

Charts: assessment mean, objective attainment side by side, percent attainment distribution, and an objective radar chart. The radar chart uses one axis per OID and must show the selected assessment's percentage beside every objective. Draw the teacher-defined objective targets as a separate polygon. Hover and keyboard focus expose: objective ID + label, assessment type, observed %, earned/possible points, students meeting target / complete objective records, and the local target. If the host supports an inline interactive widget, render this radar directly in the chat from verified `report.json` values. Otherwise show the static SVG and objective table in chat and provide `objective_radar.html` as the interactive portable fallback. Do not imply that a generated HTML file was rendered inline.

Teaching recommendations must be a separate section after measured results. Tie each recommendation to an OID, its observed percentage, local target and number meeting target. Prioritize objectives below target; when the aggregate meets target but many students do not, recommend differentiated follow-up rather than declaring class-wide mastery. Use score spread to flag a need for grouping or additional evidence. Suggest a specific next evidence check (for example, an aligned exit ticket or performance task), but do not make causal effectiveness claims based only on observational assessment. Use `scripts/analyze_results.py` when executable, otherwise return data and chart specifications rather than pretending plots exist.
